01系统总览

核心原则：Agent 只需会一套 memory 命令；Bridge 负责一切脏活（鉴权、脱敏、项目识别、去重、LLM 提取）；Mem0 只管存储与检索。任何一层都可独立替换。

02运行流程

场景 A · 一次典型的 agent 会话

STEP 1
会话开始
agent 按全局 AGENTS.md 指令运行 memory context
→
STEP 2
注入上下文
Bridge 识别当前项目 → 拉取偏好/知识/决策/任务/坑 → markdown 输出
→
STEP 3
工作中写入
产生决策/踩坑时 memory remember，脱敏+去重后实时入库
→
STEP 4
会话收尾
memory checkpoint 采集 git+产出，LLM 提取批量写回

checkpoint 内部流水线

git 采集                          会话产出
├─ branch / log -5               (agent 最终输出文件)
├─ status --short                      │
├─ diff HEAD --stat                    │
└─ diff HEAD (≤12KB)                   │
        └──────────┬───────────────────┘
                   ▼
        DeepSeek deepseek-chat 提取
   输出 JSON: decisions / incidents
             / completed / next_steps / profile
                   ▼
        逐条 脱敏 → content_hash 去重 → Mem0
        (metadata: type + project_id + source_agent)
跨工具共享的实现：所有记忆存同一个 user_id=beanwang 下，检索默认不按 agent 隔离。 source_agent 只标记"谁写的"。实测：codex（经 Bridge）写入 → pi（经扩展）立即可检索。

场景 B · 数据的去与回

操作 链路
写入 CLI → Bridge（脱敏 → hash 去重 → 加 metadata）→ Mem0 POST /memories（infer:false 原文存储）→ ollama 向量化 → pgvector
语义检索 CLI → Bridge → Mem0 POST /search（filters: user_id + project_id/type）→ pgvector 向量相似 → 按 score 排序返回
组装上下文 Bridge GET /memories 全量拉取 → 按 type/scope/project 客户端过滤 → 按时间排序 → 截断（5/10/10/5/5）→ markdown
删除 单条 DELETE /memory/{id}；批量 POST /forget（默认 dry-run，须显式 --execute）
为什么去重不用向量相似度：实测同一文本作为查询仅得 ~0.5 分（Mem0 存储 embedding 时混入了 metadata）， 语义阈值无法可靠区分"重复"与"相似但不同"。因此 Bridge 在 metadata 里存 content_hash（sha256）， 写入前精确匹配 —— 同 scope 同项目下逐字重复必定拦截，改写过的重复留给人工 forget 或未来 V5 consolidation。

03记忆分类（--type）

type 用途 典型示例 context 配额
profile 用户长期偏好（通常 --scope global） "偏好 pnpm 与 TypeScript strict mode" 5 条
project 项目长期知识 "API 位于 apps/api，ORM 用 Drizzle" 10 条
decision 架构/技术决策，须含结论与原因 "不再引入 Redis session，Supabase JWT 已够用" 10 条
task 进行中/已完成的工作状态 "前端上传进度条未完成" 5 条
incident 踩坑：现象+原因+解决 "Vite HMR 在 Tailscale 下失败，server.host=true 解决" 5 条

每条记忆自动附带 metadata：schema_version / scope / project_id / source_agent / source_system / content_hash / branch / task_id / tags

04CLI 使用方法

# ① 会话开始 —— 拉取当前项目+全局记忆（在任意 git 仓库内自动识别项目）
memory context
memory context --project github.com/yves/myapp   # 手动指定项目
memory context --global-only                     # 只要用户偏好

# ② 语义检索
memory search "项目用什么认证方案"
memory search "上传相关踩坑" --type incident --top-k 5

# ③ 写入（类型默认 decision；项目自动从 cwd 推导）
memory remember "决定用 Supabase Storage 存头像，不落本地盘"
memory remember "用户偏好 pnpm" --type profile --scope global
AGENT_NAME=codex memory remember "..."          # 标记来源 agent

# ④ 会话收尾 —— 自动汇总 git 变更 + 产出文件，LLM 提取后写入
memory checkpoint
memory checkpoint --repo ~/code/myapp --output-file /tmp/result.txt --agent codex

# ⑤ 修正记忆
memory forget 4bb45fcf-c5f3-4f75-860f-0dbebe8c2c07
memory forget-batch --project github.com/yves/myapp              # dry-run 预览
memory forget-batch --project github.com/yves/myapp --execute    # 真删
project_id 规则：取 git remote get-url origin 归一化（git@github.com:yves/x.git → github.com/yves/x）。 多 worktree 共享同一项目记忆；无 remote 的仓库回退 local-<路径哈希>。

05各工具接入方式

工具 接入点 记忆通道 说明
codex ~/.codex/AGENTS.md（全局） memory CLI → Bridge agent 会按指令在会话开始/收尾调用
zcode ~/.zcode/AGENTS.md（全局） memory CLI → Bridge 同上
kimi ~/.kimi-code/AGENTS.md（全局） memory CLI → Bridge 另有 hooks 体系（[[hooks]]）可做 V3 自动 checkpoint
pi pi-memory-mem0 扩展 扩展直连 Mem0（不经 Bridge） active 模式自动捕获+召回；与 Bridge 共享同一 user_id，记忆互通

原始文件均有 *.bak-mem0 备份；指令仅作后备说明，主链路已由 hooks 机制化（见下）。

⚡ 全自动 hooks（V1.1 已验证）

工具 SessionStart（自动注入） SessionEnd（自动 checkpoint）
codex ~/.codex/hooks.json → session_context_hook.py codex，经 hookSpecificOutput.additionalContext 注入 session_end_hook.py codex 异步触发（detached，不阻塞退出）
kimi ~/.kimi-code/config.toml [[hooks]] event=SessionStart [[hooks]] event=SessionEnd 同上
pi pi-memory-mem0 扩展本就全自动（捕获+召回）
zcode 暂无 hook 机制，靠 AGENTS.md 指令（其余三者已机制化）

行为：会话打开→记忆自动注入上下文（codex TUI 显示 “SessionStart hook (completed)”）；会话关闭→后台自动汇总 git 变更与 transcript 产出，DeepSeek 提取写回。空会话守卫：无 diff 且无产出时不调 LLM；content_hash 去重防止重复触发造成冗余。

注意：① codex 首次加载新 hooks 会弹一次 “Hooks need review” 信任门，选 Trust all and continue 即可（之后不再弹）；② codex 将 SessionEnd timeout 钉到 3s——hook 本身秒退（checkpoint 后台异步），无影响；③ kimi 接入同源协议，因当月配额耗尽未实测，下周期自动生效。

06HTTP API（Bridge）

基址 http://127.0.0.1:8765，所有端点（除 /health）要求 Authorization: Bearer <bridge_token>（token 在 config.json）。

端点 说明
GET /health 健康检查，无需鉴权
POST /context {"project_id"} → markdown 上下文 + total
POST /search {"query","project_id?","type?","top_k?"} → 结果列表（含 score）
POST /remember {"content","type","scope","project_id?","source_agent"} → created/skipped + id
POST /checkpoint {"repo_path","output_text?","source_agent?"} → LLM 提取并写入，返回 created 列表
DELETE /memory/{id} 删除单条
POST /forget {"project_id?","type?","source_agent?","dry_run"} → 批量删除（至少一个过滤条件）

07运维手册

服务管理（launchd）

# 状态 / 重启
launchctl print gui/$(id -u)/com.yves.agent-memory-bridge
launchctl kickstart -k gui/$(id -u)/com.yves.agent-memory-bridge

# 日志
tail -f ~/agent_memory/logs/bridge.err.log

# 健康检查
curl --noproxy '*' http://127.0.0.1:8765/health

文件布局

~/agent_memory/
├── bridge/server.py    # 单文件服务
├── cli/memory          # CLI（软链到 ~/.local/bin）
├── prompts/checkpoint.md
├── config.json         # 0600，含全部密钥
└── logs/

改 server.py 后 kickstart -k 即生效；Bridge 无状态，可随时重建（记忆都在 Mem0）。

与 Mem0 备份的关系：记忆数据由 oma 侧既有体系保护——systemd timer mem0-backup 每 6 小时快照（pg_dumpall + 定制 dump + SHA256 校验）+ restic 加密异机至 Mac；恢复演练脚本 ~/services/mem0/restore-drill.sh。Bridge 自身无状态，无需备份；config.json 含密钥，已随 0600 权限保护，如需备份请手动加密存放。

08安全边界与排错

安全设计

层 措施
网络 Bridge 仅绑定 127.0.0.1；跨设备访问 Mem0 只走 Tailscale Serve（Tailnet 内可达）
鉴权 CLI→Bridge：Bearer token（常数时间比较）；Bridge→Mem0：独立 API key mac-bridge，可单独吊销
脱敏 写入前自动擦除：私钥块 / Bearer token / api_key=... / sk-ghp-xox 令牌 / AKIA / JWT / URL 内嵌凭证
误删防护 批量删除强制 dry-run 默认 + 至少一个过滤条件；单条删除需显式 id

常见问题

现象 处理
CLI 报 bridge unreachable 服务没起来：launchctl kickstart gui/$(id -u)/com.yves.agent-memory-bridge，再看 err.log
remember/search 报 502 Mem0 侧故障：查 oma:~/services/mem0 容器状态；确认 Mac 能 curl --noproxy '*' https://omarchy.tail11e709.ts.net:8443/auth/setup-status
记忆写进了错误项目 确认 cwd 的 git remote get-url origin；或显式 --project；错的可 forget 后重写
疑似记忆被污染 memory forget-batch --project X 先 dry-run 核对 id 列表，确认后 --execute
怀疑 token 泄漏 换 config.json 里 bridge_token 并重启 Bridge；吊销 mac-bridge key 换新
